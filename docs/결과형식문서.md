# 결과 형식 문서 — 교육장 카메라 서비스 v1 (team2)

다른 팀의 대시보드·로컬 LLM 에이전트·제어 로직이 이 서비스 값을 가져다 쓰기 위한 인터페이스 설명입니다.
**영상·사진은 보드 밖으로 나가지 않고, 아래 숫자만 나갑니다.**

| 서비스 | 하는 일 | 카메라 | systemd 유닛 |
|---|---|---|---|
| 재실 인원 (A2) | 1초마다 사람 수를 세고, 30초 중앙값으로 평활해 10초마다 발행 | VIGI C540-W 서브 스트림 848×480 | `occupancy.service` |
| 키오스크 동작·행동 (A3) | 안내판 앞 사람의 동작(만세·한팔들기·손 흔들기·악수)과 행동(지나감·힐끗 봄·관심 있음·머무름) 판정 | VIGI RTSP | `pose-service.service` |

## 1. 접속 정보

| 항목 | 값 |
|---|---|
| MQTT 브로커 | 팀 Jetson의 mosquitto `127.0.0.1:1883` (QoS 1) |
| REST | `http://<젯슨 주소>:8095` (재실 인원) |
| 시각 | 재실 인원은 ISO 8601(한국 시간, `+09:00`), 키오스크는 유닉스 초(epoch). 두 서비스의 형식이 다르니 받는 쪽에서 맞춘다 |

> ⚠️ **주의: 지금 브로커는 보드 안(127.0.0.1)에서만 열려 있습니다.** 다른 팀이 네트워크로 구독하려면 둘 중 하나가 필요합니다.
> 1. mosquitto 설정에 `listener 1883 0.0.0.0`을 추가합니다(+ 인증).
> 2. 팀 공용 브로커(1885)로 `aiot/#`을 브리지합니다.
>
> 그 전까지는 REST(8095)로 조회할 수 있습니다.

## 2. MQTT 토픽

| 토픽 | 발행 주기 | retain | 내용 |
|---|---|---|---|
| `aiot/space/<공간>/occupancy` | **10초마다** | ✅ | 공간별 현재 재실 인원 |
| `aiot/service/occupancy/status` | 시작·정상 종료 때 | ✅ | 재실 인원 서비스 온라인 여부 |
| `aiot/kiosk/<공간>/status` | **1분마다** | ✅ | 키오스크 서비스 상태 |
| `aiot/kiosk/<공간>/event` | **일이 생긴 즉시** | ❌ | 동작·행동 이벤트 1건 |
| `aiot/kiosk/<공간>/summary` | **15분마다** | ✅ | 최근 15분 이벤트 집계 |

retain이 켜진 토픽은 **새 구독자가 접속하자마자 마지막 값을 받습니다.** 이벤트는 그 순간에만 의미가 있어 retain을 끕니다(재접속할 때 옛 이벤트가 다시 오면 안 됨).

### 2-1. `aiot/space/<공간>/occupancy` (재실 인원)

실제 메시지 (2026-11-03 09:14, 빈 강의실):
```json
{"ts": "2026-11-03T09:14:15+09:00", "space": "lab1", "count": 0, "raw": 0, "unit": "명",
 "window_s": 30.0, "stat": "median", "age_s": 0.0, "camera": "정상", "reconnects": 0}
```

| 필드 | 형식·단위 | 뜻 |
|---|---|---|
| `ts` | ISO 8601 | 값을 만든 시각 |
| `space` | 문자열 | 공간 이름 (`lab1`) |
| `count` | 정수, 명 | **제어에 쓰는 값.** 최근 `window_s`초 동안 센 값의 `stat`(중앙값) |
| `raw` | 정수, 명 | 가장 최근 프레임 하나에서 센 값. 깜빡임이 있으니 제어에는 쓰지 않고, 반응 속도·오검출 분석용 |
| `unit` | 문자열 | `명` |
| `window_s` | 초 | 평활 창 (30초) |
| `stat` | `median` / `p75` / `max` | 평활 방법 |
| `age_s` | 초 | 마지막 프레임이 얼마나 오래됐는지. **5초를 넘으면 그 값은 믿지 않는다** (서비스도 5초 넘은 프레임은 세지 않음) |
| `camera` | `정상` / `연결 중` / `끊김(재연결 중)` / `끊김(프레임 없음)` | 카메라 상태. 읽기에 실패하면 `끊김(재연결 중)`. 랜선이 빠지면 읽기가 오류 없이 멈추므로, 마지막 프레임이 5초 넘게 없으면 `끊김(프레임 없음)` |
| `reconnects` | 회 | 서비스 시작 뒤 카메라 재연결 횟수 |

카메라가 아직 연결 중이면 `count`, `raw`, `age_s`는 `null`입니다. 받는 쪽은 `null`을 0으로 바꾸지 않습니다. 0이면 빈 방으로 잘못 판단합니다.

### 2-2. `aiot/service/occupancy/status`

```json
{"status": "online", "ts": "2026-11-03T08:53:07+09:00"}
```
- `online` / `offline`
- ⚠️ 지금은 `paho-mqtt`가 설치돼 있지 않아 `mosquitto_pub` 명령으로 발행합니다. 그래서 **비정상 종료(전원 차단 등) 때는 `offline`이 오지 않고 `online`이 남습니다.** `paho-mqtt`를 설치하면 코드에 이미 있는 유언 메시지(LWT)가 동작해 브로커가 `offline`을 대신 보냅니다. 그 전까지는 2-1 메시지의 `ts`가 30초 넘게 멈추면 꺼진 것으로 봅니다.

### 2-3. `aiot/kiosk/<공간>/status` (키오스크 상태, 1분마다)

```json
{"ts": 1793664844, "fps": 20.4, "people": 0, "reconnects": 0, "frame_age_s": 0.1, "mem_avail_mb": 1744}
```

| 필드 | 단위 | 뜻 |
|---|---|---|
| `ts` | 유닉스 초 | 상태 시각 |
| `fps` | 프레임/초 | 최근 처리 속도 |
| `people` | 명 | 지금 화면의 사람 수 |
| `reconnects` | 회 | 카메라 재연결 횟수 (프로세스가 다시 시작되면 0부터) |
| `frame_age_s` | 초 | 마지막 프레임 나이. **크면 카메라가 끊긴 것** |
| `mem_avail_mb` | MB | 보드 여유 메모리 |

### 2-4. `aiot/kiosk/<공간>/event` (즉시)

```json
{"ts": 1793661464.22, "who": "#13", "label": "관심 있음"}
```
- `who`: 추적 번호(얼굴·이름이 아님). 화면에서 3초 이상 사라졌다가 돌아오면 새 번호가 됩니다.
- `label`: `만세`, `한팔들기`, `손흔들기`, `악수`, `지나감`, `힐끗 봄`, `관심 있음`, `머무름`

### 2-5. `aiot/kiosk/<공간>/summary` (15분마다)

```json
{"ts": 1793664544, "window_s": 900, "counts": {"지나감": 2}}
```
- 최근 15분 동안 라벨별 이벤트 수입니다. 안내판 효과(지나감 대비 관심 있음 비율) 계산에 씁니다.

## 3. REST (재실 인원, 포트 8095)

| 주소 | 내용 |
|---|---|
| `GET /occupancy` | 공간별 최신 값 (MQTT 2-1과 같은 형식, `{ "lab1": {...} }`) |
| `GET /health` | 서비스 상태 |

`/health` 예 (2026-11-03 09:08):
```json
{"uptime_s": 923, "mqtt_connected": true,
 "cams": {"lab1": {"status": "정상", "reconnects": 0, "frames": 22762}},
 "infer_ms_avg": 47.4, "saved_images": 0, "cpu_pct": 21.8, "mem_used_mb": 5708, "gpu_pct": 5.9}
```
- `saved_images`: 서비스가 저장한 사진 수. **운영 모드에서는 항상 0**이어야 합니다.

## 4. 받는 쪽 권장 사항

| 상황 | 권장 |
|---|---|
| 냉난방·노쇼 판정 | `count`만 씁니다. `age_s > 5`이거나 `camera ≠ 정상`이면 "모름"으로 처리합니다 |
| 빈 방 판정 | `count == 0`이 **5분 넘게 이어질 때만** 빈 방으로 봅니다(한두 번의 놓침 방지) |
| 로컬 LLM 도구 | 값과 함께 `ts`·`age_s`(얼마나 오래된 값인지), `camera`·`reconnects`(얼마나 믿을 만한지)를 같이 넘깁니다 |
| 서비스 감시 | 재실 인원 `ts`가 30초 넘게 멈추거나, 키오스크 `status`가 2분 넘게 안 오거나 `frame_age_s`가 크면 알림을 보냅니다 |

## 5. 갱신 주기를 다르게 둔 이유

| 값 | 주기 | 이유 |
|---|---|---|
| 재실 인원 | 10초 | 30초 평활 값이라 그보다 자주 보내도 바뀌지 않습니다. 냉난방 제어에는 10초면 충분합니다 |
| 동작·행동 이벤트 | 즉시 | 손짓 호출처럼 바로 반응해야 하는 용도입니다 |
| 상태·집계 | 1분, 15분 | 감시·통계용이라 자주 보낼 필요가 없습니다 |
| (거리 알람) | 상태가 바뀔 때만 | 매 프레임 보내면 초당 수십 건이 쌓여 받는 쪽이 같은 알람을 반복 처리합니다 |
